# 10ビット言語分類モデルの作成手順

OpenAIの多言語版Whisper tinyから言語判定用のONNXを作り、そのONNXと同じ量子化済みの重みをGGUFに格納した。FLEURSの開発分割は基準版の量子化方式の選定と小型版の低ランク近似の校正に、テスト分割とEmilia-YODASは精度の評価に使用した。勾配を使った追加学習は行っていない。

## 1. 公式の重みを読み込む

変換元は `openai/whisper` の多言語版 `tiny`（ファイル名 `tiny.pt`）。公式パッケージ `openai-whisper==20250625` のモデル一覧からチェックポイントを取得し、下表のSHA-256と照合した。公式コードとモデル重みのライセンスはMITで、著作権表示は **Copyright (c) 2022 OpenAI**。配布モデルにもライセンス本文を同梱した。[公式リポジトリ](https://github.com/openai/whisper/tree/v20250625) · [公式のモデル一覧](https://github.com/openai/whisper/blob/v20250625/whisper/__init__.py) · [公式チェックポイント](https://openaipublic.azureedge.net/main/whisper/models/65147644a518d12f04e32d6f3b26facc3f8dd46e5390956a9424a650c0ce22b9/tiny.pt) · [公式ライセンス](https://github.com/openai/whisper/blob/v20250625/LICENSE) · [同梱のライセンス](../model/LICENSE)

## 2. 99言語のスコアだけを計算する

PyTorch 2.6.0でモデルをCPU・評価モード・FP32で読み込んだ。音声エンコーダーを保持し、デコーダーの入力は開始トークン（SOT）1個に固定した。初期状態にはSOTの埋め込みと先頭位置の埋め込みの和を使った。

各デコーダーブロックの自己注意は、参照先が1個なら注意確率が常に1になるため、値と出力の射影だけで計算できる。音声エンコーダー出力への交差注意とMLPは保持した。最後の出力射影には、公式トークナイザーの言語トークン99個に対応する埋め込み行だけを使い、トークンIDの昇順を出力順として保存した。[言語表](../model/languages.json)

## 3. ONNXに書き出し、重みを10ビットで格納する

量子化前にゼロのメル入力を使い、専用グラフの出力と元のWhisperの先頭トークンにおける99言語のスコアを照合した（絶対許容誤差 `1e-5`、相対許容誤差 `1e-4`）。続いてPyTorchのONNXエクスポーターとONNX 1.17.0を使い、opset 17、入力 `mel [1, 80, 3000]`、出力 `logits [1, 99]` のFP32グラフを書き出した。公式の80バンドのメルフィルターと400サンプルのHann窓を別途保存した。[前処理用係数](../model/frontend.npz)

1. 定数を右辺に持つ `MatMul` の重み行列を転置して平坦化し、末尾をゼロ埋めして60要素ずつに分割した。
2. 各ブロックのスケール `s` は `max(max(abs(w)) / 511, 2^-14)` とした。各重みを `s` で割り、最近接整数（ちょうど中間なら偶数）に丸め、−511～511に収めてから511を足して符号なしコードにした。コードの計算後、保存用のスケールをFP16に変換した。
3. 32ビットワードのビット位置0、10、20にコードを3個ずつ詰めた。ONNXグラフにコードの取り出しと `(code - 511) × 保存したスケール` によるFP32への復元を組み込み、元の行列形状に戻して積を計算するようにした。ほかの浮動小数点定数は、8要素以上でFP16に往復しても全値が一致するものをFP16で格納した。

FLEURSの開発用240条件例で、元のtinyが正解したケースを新しく誤らなかった候補のうち、最小だった10ビット版を採用した。選定に使わなかった80録音から作った160条件例（元音声・先頭3秒・雑音付加）では、元のtinyと10ビット版の第1候補が全件一致し、ともに147件正解だった。[配布ONNX](../model/lid.onnx)

## 4. 同じ重みをGGUFに移す

採用したONNXのSHA-256を確認してから、各行列のパック済み32ビットワードとFP16スケールをそのままGGUF v3のテンソルに移した。この段階での再量子化は行っていない。畳み込み・正規化・位置埋め込みなどの定数、メルフィルター、Hann窓、99言語の出力順も収録した。アーキテクチャ名は `whisper-lid10`。Rust側はロード時に重みを展開し、ggmlで分類グラフを構築してCPUまたはVulkanで実行する。[配布GGUF](../model/lid10.gguf) · [重みの復元](../src/weights.rs) · [推論グラフ](../src/engine.rs)

## 校正付きランク96版

基準の10ビット重みを浮動小数へ展開し、デコーダーの4ブロックを次の順で変換した。エンコーダーは基準版と同じ重みを使用する。

1. **固定計算をまとめる。** 第1ブロックには常に同じ開始状態が入る。自己注意後の残差ベクトルと、交差注意で音声の各位置を採点する6ヘッド分のベクトルを事前計算した。残り3ブロックでは、自己注意のvalue射影と出力射影を、バイアスを含む1個の線形変換に合成した。
2. **音声から各行列の入力分布を測る。** FLEURSの開発分割から日本語、英語、中国語、韓国語、ドイツ語、フランス語、スペイン語、ヒンディー語を各20録音、計160録音使用した。1録音につき各ブロックのMLPの2つの線形変換（384→1,536、1,536→384）の入力をそれぞれ1個記録した。各言語の `audio/dev.tar.gz` に格納された順で、先頭20個のWAVを選んだ。言語ラベルは校正計算に使用していない。[FLEURS固定リビジョン](https://huggingface.co/datasets/google/fleurs/tree/70bb2e84b976b7e960aa89f1c648e09c59f894dd/data)
3. **8個の行列をそれぞれランク96で近似する。** 線形変換を `Wx + b`、入力の平均を `μ`、平均を引いた入力を行に並べた行列を `X` とする。`Y = X Wᵀ`、`λ = 0.1 × mean(X²)` として、`YᵀY / 160 + λ W Wᵀ` を倍精度で固有値分解した。最大の96固有値に対応する正規直交列を並べた `P` から、2つの行列を `A = PᵀW`、`B = P` とした。近似後の出力は `B(Ax) + b′` で、`b′ = b + Wμ − BAμ` として校正入力の平均で元の変換と一致させた。GELUは384→1,536の変換を両因子とバイアスで計算した直後に適用する。
4. **10ビットで格納する。** 合成した3個の線形射影と、MLPの8対の因子行列に、基準版と同じ60要素単位の10ビット量子化を適用した。第1ブロックの事前計算ベクトルと新しいバイアスはFP32で保存した。GGUFとONNXは同じパック済み重みとスケールを使用し、ONNXには基準版の音声エンコーダーグラフと新しいデコーダーを接続した。

パラメータ数は基準版15,953,664、小型版11,675,904。どちらもエンコーダーの固定位置埋め込み、特徴抽出用の係数、量子化スケールは除外し、推論に使うバイアスと事前計算済みベクトルは含めて数えた。MLPの各行列の重みは `384 × 1,536 = 589,824` 個から `96 × (384 + 1,536) = 184,320` 個になり、8行列で3,244,032個減った。固定計算と射影の合成による1,033,728個を合わせて、合計4,277,760個の削減となる。

## エンコーダーを圧縮したCompact版

1. ランク96版と同じFLEURS開発分割160録音を使い、エンコーダー4層のMLPでGELU直後の1,536チャネルの出力を記録した。各録音から発話長に相当する範囲と、末尾のパディングを含む全1,500位置の範囲で、それぞれ96位置を復元抽出した（NumPy乱数シード42）。1層当たり30,720行の標本になる。
2. 各層で入力の平均を `μ`、中心化した共分散を `C`、MLPの出力行列を `W` とした。`H = C + 0.005 × mean(diag(C)) I` を作り、各チャネル `j` を `sum(W[:,j]²) / (H⁻¹)[j,j]` の降順で選んだ。採用候補は4層とも1,408チャネル。選んだ添字を `K` として、第1の線形変換の出力行とバイアスを取り出し、第2の重みを `W′ = W H[:,K] (H[K,K])⁻¹`、バイアスを `b′ = b + Wμ − W′μ[K]` に更新した。
3. この処理で4層合計 `4 × 128 × (384 + 1 + 384) = 393,728` パラメータを削減した。エンコーダーの注意射影4個とMLP行列2個の計24行列を、行方向に連続する32重みごとに8ビット化した。各ブロックでは最大絶対値を127で割ってスケールを求め、対称な整数値（−127～127）とFP16スケールを保存した。デコーダーはランク96版を使用した。
4. エンコーダーの第2層の出力で、時間方向の隣接2位置をチャネルごとに単純平均した。前半2層では20 ms間隔の1,500位置、後半2層とデコーダーの交差注意では40 ms間隔の750位置を処理する。最大入力長は30秒。この平均には追加のパラメータを使わない。
5. GGUF v3の標準テンソル型 `Q8_0` で保存した行列を、Vulkanでは量子化したままggmlに渡す。CPUではロード時に一度だけFP32に展開する。2層の畳み込みはCPU・Vulkanともに元のFP16重みとFP16入力パッチを使い、CPUでは音声長に合わせて計算範囲を選ぶ。モデルのメタデータにアーキテクチャ `whisper-lid-cal96-q8`、MLP幅、時間平均を行う層番号を記録した。
6. ONNXにはエンコーダーの同じ8ビット重みとブロックごとのスケールを格納し、FP32に復元して行列積を計算する。各層の自己注意はONNX Runtime用の `com.microsoft.MultiHeadAttention`（6ヘッド、スケール0.125）に置き換えた。メル入力と99言語の出力順は基準版と共通。CPU実行にはONNX Runtime 1.22.1を使用した。
